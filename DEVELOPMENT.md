# Development

## Make targets

The `Makefile` is generated by [bmk](https://github.com/bitranox/bmk) (its first line reads
`# BMK MAKEFILE <version>`) and is rewritten by bmk itself, so this file does not copy its target
list. `make help` prints the current targets with their aliases; `bmk --help` documents the CLI behind
them.

Two targets are specific to this repository:

- `make run` - runs the `lib_log_rich` CLI (`make run ARGS="logdemo --theme neon"`).
- `make logdemo` - runs the logging demonstration.

bmk reports in JSON by default, which hides a passing command's own output; set
`BMK_OUTPUT_FORMAT=text` to see what `make run` printed.

## Everyday workflow

```bash
make dev        # editable install with the dev extras
make test       # ruff (lint + format), pyright, import-linter, pip-audit, pytest with doctests and coverage
make test-all   # pytest + pyright on every Python version the classifiers declare, free-threaded cells included
make push       # make test, then commit and push
```

`make test` is the gate before every push. It provisions `.venv` from `uv.lock` first, and it can raise
dependency floors in `pyproject.toml` and regenerate the Makefile; commit that churn with your change.

## Versioning and metadata

- `pyproject.toml` (`[project]`) is the single source of truth for the version and package metadata.
- bmk regenerates `src/lib_log_rich/__init__conf__.py` from it during `make bump-*` and before every
  `make commit` / `make push`; never edit that module by hand.
- `make bump-patch`, `make bump-minor` and `make bump-major` raise the version; add the release's
  `CHANGELOG.md` section under that version.

## CI and publishing

The workflows under `.github/workflows/` come from the shared `default_cicd_public` template; change
them there, never in this repository.

- `default_cicd_public.yml` runs on every push and pull request: lint, type check and the test suite
  on Linux, macOS and Windows for every Python version in the `pyproject.toml` classifiers, plus the
  free-threaded versions listed under `[tool.ci] free-threaded`.
- `default_release_public.yml` runs for a `v*.*.*` tag and publishes to PyPI: with a `PYPI_API_TOKEN`
  secret when one is set, otherwise through the PyPI Trusted Publisher.
- `codeql.yml` runs GitHub's code scanning.

Release: `make release` tags the current version and creates the GitHub release, which starts the
publish workflow. It does not bump; bump and commit first. `make ship` runs push, the CI wait, the
release and the release CI wait in one go.

## Codecov

`make test` writes `coverage.xml`; `make codecov` uploads it. Public repositories need no token; for a
private one set `CODECOV_TOKEN` in `.env` (see `.env.example`) or the environment.
